# Подключение ARENA X к Supabase PostgreSQL

Проект использует Laravel 12 и прямое серверное подключение к PostgreSQL Supabase. Запросы к базе выполняет Laravel; ключи Supabase в браузер не помещаются.

## Быстрая локальная настройка на Mac

Из корня репозитория выполните:

\`\`\`bash
bash scripts/connect-supabase.sh
\`\`\`

Скрипт запросит Database Password скрытым вводом, запишет параметры подключения в локальный \`.env\`, очистит конфигурационный кеш, применит безопасную базовую миграцию и загрузит демонстрационные данные.

Пароль не выводится на экран, не передаётся в GitHub и не записывается в исходный код.

## Если прямое подключение недоступно

В Supabase Dashboard откройте проект \`arena-x\` → **Connect** → **Connection string**. Если сеть не поддерживает прямое подключение, используйте **Session Pooler** и замените \`DB_HOST\`, \`DB_PORT\` и \`DB_USERNAME\` в локальном \`.env\` на значения из панели.

## Важно

- Никогда не коммитьте \`.env\`.
- Не используйте \`service_role\` / secret key в HTML, JavaScript или Vite-переменных.
- RLS включён на таблицах. Laravel обращается к базе через доверенное серверное PostgreSQL-подключение, а пользовательские права дополнительно проверяются серверными middleware и контроллерами.
- Базовая миграция пропускает уже существующие таблицы Supabase и не удаляет их при rollback.
- Не запускайте \`php artisan migrate:fresh\` на общей базе: команда удалит таблицы и данные.
- Для локальной офлайн-разработки оставьте SQLite из корневого \`.env.example\`.

## Публичный сервер

Для production задайте \`APP_ENV=production\`, \`APP_DEBUG=false\`, публичный \`APP_URL\`, HTTPS и отдельные защищённые переменные окружения. Не используйте демонстрационные пароли в реальной эксплуатации.
